# 新建 Hexo 笔记

## 执行原则

- 只处理用户当前要创建的文章，不修改无关笔记
- 以当前仓库中的模板、文章和配置为准，不凭记忆替换仓库约定
- 必须使用 `npx hexo new post` 生成文章文件，不手工创建空文件或复制旧文章
- 标题不得带章节号、序号或编号前缀，例如 `1.`、`01`、`第 1 章`
- 技术名称中的版本号属于主题内容时可以保留，例如 `Python 3`
- 将正文写成简洁的中文技术笔记，优先使用分级无序列表承载说明
- 不在文章末尾追加独立的注意事项、补充说明或泛泛总结

## 读取仓库上下文

- 在仓库根目录开始工作
- 先读取文章模板

  ```bash
  sed -n '1,220p' scaffolds/post.md
  ```

- 检索现有文章的标题、分类、tag 和章节结构

  ```bash
  rg -n --glob 'source/_posts/*.md' '^(title|date|categories|tags|mathjax):|^# |^## |^### ' source/_posts
  ```

- 按主题选择至少两篇相近文章阅读正文，观察以下内容
  - 中文和英文技术名词的组合方式
  - `#`、`##`、`###` 的章节层级
  - 解释、命令、配置和代码之间的列表嵌套关系
  - 行内代码、代码语言标记和代码块缩进
  - `<!-- placeholder -->` 与 `<!-- more -->` 的位置
- 读取 `_config.yml`，确认文章目录、日期格式和 Hexo 写作配置
- 主题涉及第三方库、框架、命令或会变化的 API 时，使用 mcp-hub 的 Context7 查询对应官方文档后再写入事实
- 文档查询使用 Context7，不使用 Web 搜索

## 确定标题和 front matter

- 参照相近文章使用 `主题: 具体内容` 的标题形式，标题简洁、可检索且不带编号
- 让 `npx hexo new post` 生成标题和日期，再在生成文件上补全分类、tag 与 `mathjax`
- 保留 scaffold 已生成的字段和顺序，通常包含以下字段

  ```yaml
  title: "主题: 具体内容"
  date: 2026-08-27T00:00:00.000Z
  categories: []
  tags: []
  mathjax: false
  ```

- 标题包含冒号、引号或其它 YAML 特殊字符时，为整个标题加引号，避免破坏 front matter
- 只在正文确实使用 LaTeX 或 MathJax 公式时设置 `mathjax: true`，否则保持 `false`
- 按宽到窄排列分类，并优先复用仓库中已有的精确拼写和大小写
  - 编程语言、标准库或语言生态通常使用 `Programming` → 语言 → 领域或库
  - 工具和基础设施通常使用 `Tools & Utilities` → 工具类型 → 产品
  - 课程笔记通常使用 `SE Courses` → 课程名称
  - 算法笔记通常使用 `Algorithm` → 算法主题
  - 机器学习笔记通常使用已有的 `ML/DL` 或相近分类
- 根据文章的主要概念选择少量具体 tag，优先复用相近文章的 tag
  - 可以包含语言、框架、核心概念和使用场景
  - 不添加与正文无关的泛化 tag，不重复添加相同 tag
  - 没有合适的旧分类时才创建新分类，并让命名与现有层级一致

## 创建文章

- 根据用户主题确定不带编号的标题，并使用 shell 安全的引号包住标题
- 在仓库根目录执行以下命令

  ```bash
  npx hexo new post '<title>'
  ```

- 以命令输出的路径为唯一编辑目标，通常位于 `source/_posts/`
- 用 `git status --short` 确认新文件，只编辑本次命令生成的文件
- 保留 scaffold 生成的 `<!-- placeholder -->` 和 `<!-- more -->`，从 `<!-- more -->` 后开始写正文
- 不用手工重排或重建整个 front matter，只修改新文章所需字段

## 编写正文

- 使用一个不带编号的 `#` 标题概括文章主题
- 用 `##` 划分主要内容，用 `###` 划分必要的子主题
- 让说明内容统一落在无序列表中
  - 每个列表项表达一个事实、步骤、定义、对比或结论
  - 用两个空格嵌套相关细节，用四个空格继续细分
  - 把较长的解释拆成多个列表项，不写连续的大段正文
  - 需要提醒时，将提醒放在相关概念第一次介绍的列表项中
  - 不使用有序列表、独立的结尾说明段或单独的“注意事项”章节
- 用反引号标记 API、命令、配置字段、类型名、文件名和关键术语
- 代码块必须属于一个列表项，并保持与该列表项相同的外层缩进
  - 一级列表项下的代码围栏缩进两个空格
  - 二级列表项下的代码围栏缩进四个空格
  - 开始围栏、结束围栏和代码每一行都保留外层缩进，代码本身的语言缩进在此基础上增加
  - 为代码围栏标注语言，例如 `go`、`java`、`yaml`、`bash` 或 `sql`
- 正文句子结尾不主动添加中文句号 `。` 或英文句号 `.`，代码、命令、域名、版本字符串和文件名内部的点不改
- 保持仓库已有的简洁技术表达，不添加与主题无关的背景、重复结论或空泛评价
- 文章需要公式时使用仓库已有的 MathJax 写法，并同步检查 `mathjax` 字段

## 完成检查

- 检查新文章的 front matter 可以被 YAML 解析，字段顺序和 scaffold 基本格式保持一致
- 检查标题与各级章节标题没有章节编号或序号前缀
- 检查 `<!-- more -->` 存在且正文位于其后
- 检查正文说明使用无序列表，列表层级表达了内容关系
- 检查每个代码块的外层缩进与所属列表项一致，代码内部缩进没有被破坏
- 检查分类从宽到窄，tag 与文章主题直接相关，并尽量复用了现有命名
- 检查正文句末没有新增中文句号或英文句号
- 执行空白检查

  ```bash
  git diff --check
  ```

- 依赖已安装且改动涉及 front matter 或 Markdown 结构时，执行 Hexo 构建验证

  ```bash
  npx hexo generate
  ```

- 最终只用无序列表简短报告新文章路径、标题、分类和 tag，不附加额外注意事项
